# Полевые испытания Step9F — точная последовательность

## 0. Подготовить дома

1. Распаковать архив Step9F в отдельную папку.
2. Открыть в VS Code именно папку, где лежит `platformio.ini`.
3. В PlatformIO открыть:

   ```text
   PROJECT TASKS
   └─ mega_v6_he200_waveshare_readonly
      └─ General
         └─ Build
   ```

4. Дождаться `SUCCESS`.
5. Подключить Mega и выполнить `Upload` в той же среде.
6. При нескольких COM-портах использовать терминал:

   ```text
   pio run -e mega_v6_he200_waveshare_readonly -t upload --upload-port COM6
   ```

   Вместо `COM6` указать фактический порт.
7. Один раз открыть Monitor и проверить начало:

   ```text
   V6 SYSTEM STEP9F FIELD DIAGNOSTICS START
   FW: v6-system-step9f-field-diagnostics
   HE200 commissioning profile enforced in RAM: 9600 8-N-1
   RS485 transceiver direction: AUTO/Waveshare
   Physical AUTO/HOME interlock: BLOCKED
   ```

8. Закрыть PlatformIO Monitor.
9. Запустить:

   ```text
   tools\telfer_service_console\start_console.bat
   ```

10. В Chrome/Edge нажать `Подключить COM`, выбрать Mega и проверить, что приложение принимает строки.
11. Нажать `Сохранить журнал` и убедиться, что текстовый файл создаётся.

## 1. Перед работой на объекте

1. Убедиться, что груз и люди не находятся в опасной зоне.
2. Проверить штатный физический аварийный останов.
3. Не менять существующие параметры клеммного управления HE200.
4. Не переводить `P0.02` в communication control.
5. Все движения выполнять только существующим физическим пультом.
6. При любом неожиданном движении прекратить испытание и снять питание с исполнительной части.

## 2. Один HE200, короткий кабель

### 2.1. Подключение при снятом питании

```text
Mega 5V       -> Waveshare VCC
Mega GND      -> Waveshare GND
Mega TX1/18   -> Waveshare RXD
Mega RX1/19   <- Waveshare TXD
Waveshare A+  -> HE200 A+
Waveshare B-  -> HE200 A-
```

Дополнительно:

```text
pin 6 Mega = не подключён
SGND = не подключён
120R = OFF
```

### 2.2. Настройки первого HE200

```text
Pd.00 = 0005     9600
Pd.01 = 3        8-N-1
Pd.02 = 1        address H1
Pd.03 = 2 ms
Pd.04 = 0.0
Pd.05 = 01       Standard Modbus
Pd.06 = 0
```

### 2.3. Проверка

1. Включить оборудование.
2. Запустить сервисную консоль.
3. Подключить COM Mega.
4. Нажать `Тихий журнал`.
5. Нажать `Профиль 9600 8N1`.
6. Нажать `H1`.
7. Дождаться полного цикла чтения.

Успех:

```text
@HE200 name=H1 addr=1 online=1 ... fault=0x0 ... error=0
```

Прекратить этап при:

```text
@HE200 name=H1 addr=1 online=0 error=1
```

или если в журнале появляется `MODBUS TX FC06`. В READ-ONLY сборке FC06 появляться не должен.

При таймауте последовательно проверить, не меняя несколько вещей одновременно:

1. светится ли PWR Waveshare;
2. мигает ли RXD при запросе;
3. мигает ли TXD при ответе;
4. адрес `Pd.02=1`;
5. `Pd.01=3`;
6. A+ и B-;
7. только при снятом питании один раз поменять A/B для проверки разной маркировки;
8. сохранить журнал и не переходить к четырём ПЧ.

## 3. Все четыре HE200

1. Снять питание перед изменением шины.
2. Собрать последовательную двухпроводную шину, не звезду.
3. Проверить адреса:

   ```text
   H1 = 1
   H2 = 2
   V1 = 3
   V2 = 4
   ```

4. Включить оборудование.
5. В приложении по очереди нажать `H1`, `H2`, `V1`, `V2`.
6. После четырёх успешных ответов нажать `Все ПЧ`.
7. Сохранить журнал с именем этапа, например `01_HE200_all_idle.txt`.
8. Зажать физическую кнопку одного привода и во время движения нажать соответствующий тест HE200.
9. После остановки повторить тест.

При движении ожидается изменение `run`, `outV`, `outI`, `DI` и `state`. Команды движения по RS485 не используются.

## 4. Четыре лазера в покое

1. Снять питание перед подключением датчиков.
2. Подключить X1, X2, Z1, Z2 к уже принятой карте SC16.
3. Включить систему.
4. В приложении нажать `Реинициализация`.
5. Подождать 5 секунд.
6. Нажать `Состояние`.

Для точного совместимого протокола ожидается по каждому каналу:

```text
hw=1
ack=0x3F
missing=0x0
nack=0x0
freq=10
rate10 примерно 100
crc=0
uartOE/PE/FE/BI/FIFO=0
```

Если поток измерений идёт, но ACK отличается, не выполнять бесконечные повторные настройки. Сохранить журнал: возможна протокольная особенность клона.

Если `nack` не равен нулю — команда отвергнута; сохранить журнал и остановить перенастройку этого канала.

## 5. Сравнение 5, 10 и 20 Гц

Для каждого режима выполнить один и тот же маршрут, с одинаковой скоростью и одинаковыми отражающими мишенями.

### 5 Гц

1. Задать в приложении продолжительность, например 90 секунд.
2. Нажать `Начать 5 Гц`.
3. Дождаться сообщения о старте теста.
4. Проехать от ближней точки к дальней и обратно.
5. Дождаться автоматического завершения либо нажать `Завершить сейчас`.
6. Сохранить журнал как `02_laser_5Hz.txt`.

### 10 Гц

Повторить без изменения маршрута. Журнал: `03_laser_10Hz.txt`.

### 20 Гц

Повторить без изменения маршрута. Журнал: `04_laser_20Hz.txt`.

Выбирать рабочую частоту не по максимальному числу кадров, а по совокупности:

- минимальный `sensorErr`;
- нулевые `crc` и `uart*`;
- отсутствие длинных `age`;
- фактический `rate` близок к заданному;
- достаточная плавность координат для AUTO.

## 6. Совместная проверка

1. Оставить прошивку READ-ONLY.
2. Запустить выбранный режим лазеров.
3. Обнулить статистику.
4. Перемещать тельферы физическим пультом.
5. В движении выполнить `Все ПЧ` и затем `Состояние` лазеров.
6. Нажать `Полевой отчёт`.
7. Сохранить общий журнал как `05_combined_field_report.txt`.

## 7. Что прислать для анализа

Обязательно прислать:

1. полный лог запуска Step9F;
2. `01_HE200_all_idle.txt`;
3. три лога 5/10/20 Гц;
4. `05_combined_field_report.txt`;
5. фото положения переключателя 120R;
6. краткую пометку, на каком участке маршрута визуально возникло подвисание.

## 8. Что завтра не делать

- не включать физический AUTO/HOME;
- не отправлять команды записи HE200;
- не менять источник команд HE200;
- не удалять legacy-код до завершения испытаний;
- не менять одновременно частоту, разводку SC16 и оптическую мишень: иначе результат невозможно интерпретировать.
