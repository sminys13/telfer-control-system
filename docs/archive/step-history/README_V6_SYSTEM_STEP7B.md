# V6 System Step7B — NE200 Modbus RTU dry-run

Этот шаг подключает к актуальной V6-сборке **уже существующие** файлы проекта:

- `include/modbus.h`, `src/modbus.cpp`;
- `include/motors.h`, `src/motors.cpp`;
- `include/utils.h`, `src/utils.cpp`.

Они адаптированы к `config_v6_bringup.h`, `SettingsV6`, четырём адресам из EEPROM и текущему слою `MotorControlV6`.

## Что не изменено

- активная среда PlatformIO: `mega_v6_sensor_core_fast`;
- DWIN-команды ручного режима `0x0101..0x010C`, `0x010F`;
- калибровка и EEPROM версии 2;
- быстрый непрерывный опрос четырёх лазерных каналов;
- физическая передача через MAX485 по-прежнему выключена.

```cpp
static constexpr bool VFD_RS485_ENABLED = false;
static constexpr bool VFD_DRY_RUN = true;
```

Пин DE+/RE MAX485 переводится в приём, но `Serial1` в этом режиме не передаёт кадры.

## Что добавлено

1. Реальное построение кадров Modbus RTU с CRC16.
2. Функция `0x06` — запись одного регистра.
3. Функции `0x03` и `0x04` — чтение регистров.
4. Настройки baud/parity/stop bits/timeout/retries берутся из EEPROM.
5. Адреса H1/H2/V1/V2 и инверсия направлений берутся из EEPROM.
6. В одном шаге планировщика выполняется не более **одной Modbus-транзакции**.
7. Пуск разбит на две транзакции:
   - уставка `0x0002`;
   - команда направления `0x0001`.
8. Остановка разбита на две транзакции:
   - `STOP` в `0x0001`;
   - нулевая уставка в `0x0002`.
9. При переходе с одной оси на другую сначала останавливается уже движущаяся ось, затем запускается новая.
10. Периодический опрос старых регистров HE200 `0x7000...` не включён. Он будет возвращён только после проверки карты мониторинга именно используемого NE200.

## Карта управления NE200 в Step7B

```text
0x0001 — команда управления
  0x0001 — вперёд
  0x0002 — назад
  0x0003 — остановка
  0x0004 — остановка выбегом
  0x0005 — сброс ошибки

0x0002 — сетевое задание, 0...10000 = 0.00...100.00%
0x0020 — безопасное чтение состояния
0x0021 — безопасное чтение кода ошибки
```

Направление задаётся командой `0x0001/0x0002`, поэтому в регистр уставки записывается **положительная величина скорости**. Так исключено старое двойное указание направления: отрицательная уставка вместе с командой `REV`.

## Принятое механическое направление

Сохранено правило старого проекта:

```text
H1/H2: положительное направление = вперёд / вправо.
V1/V2: команда частотника Forward = вниз.
```

Поэтому:

```text
Z1/Z2 ВВЕРХ  -> команда REV;
Z1/Z2 ВНИЗ   -> команда FWD.
```

Если конкретный двигатель вращается наоборот, используется `invertDirectionMask` из настроек, без изменения кода.

## Проверка через PlatformIO Monitor

### H1 вперёд — команда `0x0101`, скорость 20%

```text
NE200 H1 addr=1 SETPOINT reg=0x0002 value=0x07D0 (2000)
MODBUS DRY TX FC06: 01 06 00 02 07 D0 2B A6
NE200 H1 addr=1 RUN FWD reg=0x0001 value=0x0001 (1)
MODBUS DRY TX FC06: 01 06 00 01 00 01 19 CA
```

### H1 назад — команда `0x0102`

```text
MODBUS DRY TX FC06: 01 06 00 02 07 D0 2B A6
MODBUS DRY TX FC06: 01 06 00 01 00 02 59 CB
```

### V1 вверх — команда `0x0107`, скорость 10% по текущему EEPROM-профилю

Будет записана положительная величина уставки, затем команда `REV`.

### Ручной стоп — команда `0x010F`

Для каждого адреса формируется безопасная пара:

```text
WRITE 0x0001 = 0x0003
WRITE 0x0002 = 0x0000
```

Для H1:

```text
MODBUS DRY TX FC06: 01 06 00 01 00 03 98 0B
MODBUS DRY TX FC06: 01 06 00 02 00 00 28 0A
```

### Безопасный тест H1 — команда `0x0204`

```text
NE200 SAFE TEST queued drive=H1 addr=1 FC03 read 0x0020..0x0021
MODBUS DRY TX FC03: 01 03 00 20 00 02 C5 C1
NE200 READ dry-run: frame built; no response expected
```

Команды `0x0205..0x0207` проверяют H2/V1/V2, `0x0208` ставит в очередь чтение всех четырёх адресов. Даже тест всех устройств выполняется по одному кадру за шаг планировщика.

## Ожидаемый стартовый вывод

```text
MotorControlV6: safe control layer initialized, NE200 dry-run scheduler enabled
Drives map applied H1/H2/V1/V2=1/2/3/4 interRequest=10ms
VfdDriverV6: existing Modbus/Drives layer connected
VfdDriverV6: physical MAX485 TX disabled; exact NE200 frames will be printed
VFD layer: Step7B existing Modbus/Drives integration; exact frames printed, MAX485 TX disabled
```

`VP_VFD_STATUS` в режиме dry-run имеет значение `2`.

## Что проверить сейчас

1. Проект собирается в `mega_v6_sensor_core_fast`.
2. После загрузки датчики и DWIN работают как раньше.
3. `0x0001` включает режим Manual.
4. `0x0101`, `0x0102`, `0x0107`, `0x0108` дают ожидаемые пары кадров.
5. `0x010F` формирует STOP + zero setpoint.
6. Watchdog через сохранённое время формирует такую же остановку.
7. Переключение с H1 на V1 сначала печатает STOP H1, затем START V1.
8. `0x0204` формирует безопасный кадр чтения и ничего не передаёт физически.

## Следующий шаг

После проверки логов Step7B можно продолжать разработку без частотников:

- добавить DWIN-диагностику очереди и последних кадров;
- подключить старую технологическую логику `app.cpp` как донор состояний;
- подготовить эмулятор четырёх Modbus-устройств;
- затем включить физический RS485 только для безопасного чтения одного NE200.
