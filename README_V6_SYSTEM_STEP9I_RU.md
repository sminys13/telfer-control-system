# V6 SYSTEM STEP9I — HE200 Service Cockpit

## Цель

Подтвердить реальное управление HE200 по найденному нативному Modbus-протоколу и сразу перейти от одиночного подтверждения к четырём приводам, парным движениям и проверке алгоритма восстановления после провалов SEN0366 — без физического AUTO.

## Подтверждённая карта HE200

```text
1000H  communication setpoint, 0…10000 = 0…100% P0.10
2000H  control word
  0001 Forward
  0002 Reverse
  0003 Forward JOG
  0004 Reverse JOG
  0005 Free/coast stop       [НЕ ИСПОЛЬЗУЕМ]
  0006 Deceleration stop     [наш штатный STOP]
  0007 Fault reset
3000H  control/status register family
701CH  communication setting value, 0.01%
703BH  current set frequency, 0.01%
703CH  current running frequency, signed 0.01%
703DH  running state
```

Для сервисного движения setpoint задаётся процентом максимальной частоты. При `P0.10=50 Гц`:

```text
10% -> 5 Гц
40% -> 20 Гц
68% -> 34 Гц
```

## Gate-модель

Ни одна стадия не заменяет предыдущую.

### Gate 1 — PRE-FLIGHT

Требуется:
- FIELD SERVICE build;
- E-STOP не активен и не latched;
- при включённом контроле limits нет активных ограничителей;
- H1/H2/V1/V2 имеют свежую телеметрию (<5 с);
- fault=0;
- runningFreq <=0.20 Гц;
- run state = STOP.

Вывод:

```text
@GATE name=PREFLIGHT result=PASS reason=FOUR_DRIVES_STOPPED_SAFETY_OK
```

### Gate 2 — Protocol 4/4

На стоящем приводе:
1. читаются 1000H/3000H/701CH/703B..703D/7000H/702DH;
2. в 1000H временно записывается 500 = 5%;
3. 701CH обязан вернуть 500;
4. на уже стоящий ПЧ отправляется `2000H=0006`;
5. исходный 1000H восстанавливается;
6. привод обязан остаться остановленным.

PASS по четырём ПЧ формирует `protocol=0xF`.

### Gate 3 — источник Modbus

После Protocol PASS оператор вручную выставляет на четырёх HE200:

```text
P0.02 = 2
P0.03 = 9
```

И подтверждает это в браузере. Этот gate локальный/операторский: он намеренно не записывает P0.xx автоматически.

### Gate 4 — индивидуальные направления

Каждый ПЧ тестируется двумя короткими импульсами не выше 20%, стандартно 10% и 1200 мс. Прошивка сама:
- задаёт 1000H;
- даёт FWD/REV;
- опрашивает телеметрию;
- отправляет 0006;
- подтверждает, что ПЧ реально вращался и остановился.

После электрического PASS оператор отдельно подтверждает визуальное направление.

### Gate 5 — пары

После 8 подтверждений направления выполняются:
- H1+H2 совместно;
- V1+V2 совместно.

### Gate 6 — Assisted motion

Доступен только после предыдущих gates выбранной оси. Service Cockpit дополнительно показывает крупный итоговый маркер GO/NO-GO и текст следующего разрешённого действия, поэтому оператору не нужно помнить последовательность вручную.

## Assisted motion

Пара движется как единое целое. По худшему возрасту двух датчиков:

```text
0…450 мс       NORMAL
451…650 мс     WARNING
>650 мс        DECEL
>1200 мс       HOLD, продолжить рамп выбранной пары до 0
>5000 мс       FAULT
```

Рамп setpoint: 5 процентных пунктов каждые 200 мс.

Если данные вернулись до остановки — 3 свежих парных кадра -> мягкий разгон к basePct.
Если пара уже остановилась — 5 свежих парных кадров -> мягкий рестарт с 5%.

## Почему это соответствует технологии

Самый тяжёлый горизонтальный проход к первой дальней зоне выполняется один раз. После него технологический цикл идёт последовательными переходами приблизительно по 1 м с уменьшением дальности до горизонтальных датчиков. Поэтому редкие длинные gaps на 8–9 м обрабатываются как штатное событие замедления, а не как причина менять систему измерения.

## Что пока сознательно отсутствует

- физический AUTO/HOME;
- free/coast stop 0005;
- автоматическое изменение P0.02/P0.03;
- управление через DWIN в FIELD SERVICE;
- 10/20 Гц лазеров, 0.1 мм, alternating single-shot в основном браузерном UI;
- энкодеры.


## Область STOP в Step9I

- `service stop` — плавный `0006` для **всех четырёх** приводов; это верхняя красная сервисная кнопка.
- `assist stop` — плавный `0006` только для **активной пары X или Z**.
- потеря одного датчика в Assisted motion снижает setpoint и при необходимости останавливает **оба привода этой пары**, не затрагивая вторую ось.
- аппаратный E-STOP остаётся независимым средством безопасности.
